# Slopify

No ads. No subscriptions. Just slop.

### Учётные записи и доступ к библиотеке

- При первом подключении клиента новый сервер предлагает зарегистрировать первого администратора через приложение. Обычные пользователи регистрируются по приглашению администратора.
- Файлы треков и обложек хранятся в общей библиотеке сервера. У каждого пользователя свои личные плейлисты. Доступ к совместным плейлистам предоставляется по приглашению.
- Любой зарегистрированный пользователь может найти исполнителя в приложении и добавить его трек или альбом. Добавление запускает загрузку выбранного трека или всех треков альбома в общую библиотеку.
- После добавления отдельного трека из неполного альбома сервер дозагружает остальные треки этого альбома, включая те, которые пользователи ещё не добавляли. Сервер запускает дозагрузку, когда очередь пользовательских загрузок пуста.
- Только администратор может редактировать метаданные общей библиотеки и удалять из неё файлы.

### Хранение треков на сервере

Треки хранятся в формате MP3 (`.mp3`), метаданные записываются в теги ID3v2.3. Сервер хранит обложку альбома отдельным файлом и отдаёт её клиенту независимо от аудио, чтобы интерфейс мог быстро загрузить изображение. Эта же обложка записывается в тег ID3v2.3 каждого MP3-файла альбома.

При загрузке сервер сохраняет трек в каталоге исполнителя, внутри каталога релиза. В серверной модели альбомы, синглы и EP относятся к одному типу «альбом».

Если источник не указал год релиза или номер трека в альбоме, эти данные нужно заполнить перед сохранением в библиотеку.

```text
Исполнитель/
└── [год] Название релиза/
    └── [номер-в-альбоме] Название трека.mp3
```

При изменении метаданных, входящих в путь, сервер переименовывает или перемещает затронутые файлы и каталоги по этой же схеме.

При замене обложки сервер обновляет отдельный файл и теги всех треков альбома.

### Развёртывание серверной части

- Rust-сервис, Python-микросервис и PostgreSQL запускаются через Docker Compose.
- Для PostgreSQL используется образ `postgres:18-alpine`.
- Для Rust-сервиса используется многоэтапная сборка с `rust:1-alpine` на этапе компиляции.
- Для Python-микросервиса используется образ `ghcr.io/astral-sh/uv:python3.15-alpine` и пакетный менеджер `uv`.
- Клиент обращается к HTTP API Rust-сервиса через интернет по HTTPS. Для публичного IP-адреса используется бесплатный сертификат Let’s Encrypt с автоматическим продлением.
- Rust-сервис вызывает Python-микросервис по gRPC во внутренней сети Docker Compose.
