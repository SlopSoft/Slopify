# Сервер Slopify

## Подготовка

Выполняйте команды из корня проекта. При первом запуске скопируйте `config/postgres.env.example` и заполните `POSTGRES_PASSWORD` в `config/postgres.env`. Случайный пароль можно сгенерировать командой `openssl rand -hex 32`.

```sh
(umask 077 && set -C && cat config/postgres.env.example > config/postgres.env)
```

PostgreSQL устанавливает пароль при первой инициализации базы. Для уже созданной базы смените пароль роли в PostgreSQL и обновите файл.

## Production

Соберите и запустите API, PostgreSQL и загрузчик. Сервер применяет миграции при запуске.

```sh
make up
curl --fail --retry 5 --retry-connrefused http://127.0.0.1:8067/health
```

API доступен на `127.0.0.1:8067`. Запрос `GET /health` возвращает `200`, если база отвечает, и `503`, если база недоступна. Для другого локального порта задайте `SLOPIFY_PORT`.

Production использует оптимизированную сборку Rust без Swagger. Финальный образ API на `scratch` запускается от непривилегированного пользователя. PostgreSQL и загрузчик доступны внутри сетей Compose.

```sh
docker compose --env-file config/postgres.env -f server/compose.prod.yaml exec postgres psql -U postgres -d slopify
make down
```

`make up` и `make down` по умолчанию работают в режиме prod. Остановка сохраняет том `slopify_postgres_data`.

### Публичный HTTPS

Добавьте в `config/postgres.env` переменную `SLOPIFY_PUBLIC_IP` с публичным IP сервера. Укажите адрес без схемы, порта и скобок. Для IPv6 используйте сокращённую запись в нижнем регистре.

Compose публикует HTTP на порту `8080` хоста и HTTPS на порту `8443`. Для публичного доступа настройте перенаправление внешних TCP-портов `80 → 8080` и `443 → 8443`. Let's Encrypt проверяет IP по HTTP на внешнем порту `80`. Caddy перенаправляет обычные HTTP-запросы на HTTPS и передаёт запросы приложений в Rust API через сеть Compose.

```sh
make up MODE=public
docker compose --env-file config/postgres.env -f server/compose.prod.yaml -f server/compose.public.yaml logs caddy
```

Caddy получает и автоматически продлевает сертификат Let's Encrypt с профилем `shortlived`. Первый выпуск происходит после запуска контейнера. После выпуска проверьте `https://<публичный IP>/health` с внешней сети и введите этот адрес без `/health` в клиенте. В URL заключайте IPv6 в квадратные скобки.

`make down MODE=public` останавливает стек и сохраняет тома PostgreSQL и Caddy. Ключи и сертификаты Caddy хранятся в томе `slopify_caddy_data`.

## Development

Для автоматической перезагрузки нужен Docker Compose 2.32 или новее. Добавьте в `config/postgres.env` отдельный пароль `PGADMIN_PASSWORD`. Почту для входа в pgAdmin можно задать через `PGADMIN_DEFAULT_EMAIL`, по умолчанию используется `admin@example.com`.

```sh
make up MODE=dev
```

Watch работает в текущем терминале. Чтобы остановить dev-сервисы из другого терминала, выполните `make down MODE=dev`.

API работает на `http://127.0.0.1:8068`, Swagger UI открывается по пути `/swagger-ui/`, а спецификация OpenAPI — по `/openapi.json`. pgAdmin доступен на `http://127.0.0.1:5050`. Для подключения в pgAdmin используйте хост `postgres`, порт `5432`, базу `slopify`, пользователя `postgres` и пароль `POSTGRES_PASSWORD`. Внешние порты задаются через `SLOPIFY_DEV_PORT` и `PGADMIN_PORT`.

Compose Watch синхронизирует исходники API, миграции, gRPC-контракт и `build.rs` и перезапускает debug-сборку с фичей `swagger`. После изменения Cargo-манифеста, lock-файла или Dockerfile образ API пересобирается. Изменения в `server/downloader/` или `server/proto/` пересобирают загрузчик. Правки в `server/dev/postgres/` и `server/dev/pgadmin/` перезапускают соответствующие контейнеры. Dev использует собственные тома PostgreSQL, pgAdmin и загруженной музыки.

## Регистрация первого администратора

Клиент проверяет `GET /setup`. Значение `registration_required: true` означает, что сервер готов принять первую учётную запись. Пока регистрация ожидается, при запуске API пишет код в строке `First administrator setup code` в журнале.

```sh
docker compose --env-file config/postgres.env -f server/compose.prod.yaml logs api
```

Для dev используйте ту же команду с `server/compose.dev.yaml`.

Отправьте в `POST /setup` JSON с полями `code`, `username` (1–64 символа) и `password` (15–128 символов). При локальной разработке это можно сделать через Swagger UI. Ответ `201` подтверждает создание администратора. Код расходуется в той же транзакции и сохраняет силу после перезапуска до успешной регистрации.

## Вход и выход

`POST /session` принимает JSON с `username` и `password`, возвращает токен в поле `token` и роль администратора в поле `is_admin`. Для получения имени пользователя передайте `Authorization: Bearer <token>` в `GET /session`. Сессия действует семь дней. `DELETE /session` с тем же заголовком отзывает её.

## Приглашения

Администратор отправляет `POST /invitations` с токеном сессии. Ответ `201` содержит одноразовый `code`, который действует 24 часа.

Приглашённый пользователь передаёт `code`, `username` и `password` в `POST /accounts`. Ответ `201` подтверждает создание обычной учётной записи и расходует приглашение. Если имя занято, сервер отвечает `409`, и пользователь может повторить регистрацию с тем же кодом и другим именем.

## Локальная библиотека

Docker Compose подключает каталог `library/` из корня проекта в режиме только для чтения. Чтобы использовать другой каталог на хосте, задайте абсолютный путь в `SLOPIFY_LIBRARY_DIR` перед запуском Compose. У пользователя контейнера с UID 65532 должен быть доступ на чтение файлов и проход по каталогам. При запуске бинарного файла напрямую `SLOPIFY_LIBRARY_DIR` указывает на каталог с медиафайлами.

При запуске API сканирует каталог и добавляет записи в PostgreSQL. Исполнителя, год, название альбома и номер трека сервер берёт из пути, например `Исполнитель/[2026] Пример/[01] Тестовый трек.mp3`. Сервер проверяет начало MP3, а имя файла определяет название трека.

Обложка необязательна. Поддерживаются JPEG, PNG и WebP до 5 МиБ. Если в альбоме несколько изображений, файлы с именем `cover` имеют приоритет. В журнал API попадают предупреждения о неверных именах, нечитаемых файлах, неподдерживаемых форматах и конфликтах номеров треков. При конфликте импорт сохраняет существующую запись. Если такой записи ещё нет, выбирает первый трек по названию и пути.

При повторном запуске идентификаторы существующих треков сохраняются. Сервер удаляет записи об исчезнувших MP3 и убирает альбомы и исполнителей, которые опустели в результате. Если удалена обложка, сервер выбирает другую подходящую или очищает ссылку. Ошибка доступа к файлу или каталогу сама по себе не удаляет записи из базы.

Войдите в клиент, откройте альбом и выберите трек. Маршруты каталога, обложек и аудио требуют токен сессии. `GET /library/tracks/{id}/audio` принимает одиночный байтовый диапазон через `Range`, а `HEAD` возвращает размер файла.

## Поиск и загрузка с YouTube

Задайте `SLOPIFY_YOUTUBE_PROXY` в `config/postgres.env` и запустите стек. Поддерживаются `http://proxy.example.org:3128`, `socks5h://proxy.example.org:1080`, `socks5://` с разрешением имён на стороне прокси и `socks4a://`. Для авторизации добавьте `user:password@` перед именем хоста и закодируйте специальные символы в учётных данных процентами. Если прокси запущен на хосте Docker, используйте `host.docker.internal` и адрес прослушивания, доступный из контейнера.

Прокси используется только для запросов yt-dlp, включая загрузку аудио и обложек. Без корректной настройки прокси загрузчик возвращает `503` через API. Локальная библиотека остаётся доступной.

В клиенте откройте **Поиск**, введите название трека и выберите **Добавить**. Сервер сохраняет каждый видеоисточник как сингл из одного трека. Если год релиза неизвестен, используется год публикации видео или текущий год. Завершённую загрузку можно открыть и воспроизвести сразу. Повторное добавление того же видео возвращает существующий релиз. Размер списка ограничен 15 результатами, длительность трека — 20 минутами. Сервер обрабатывает по одной загрузке за раз.

Загруженные файлы хранятся в томе `slopify_downloads_data` по той же схеме каталогов, что и локальная музыка. В dev используется том `slopify-dev_downloads_data`. Сохраняйте этот том вместе с PostgreSQL при резервном копировании.

При запуске API вне Compose укажите отдельный каталог для загруженных файлов в `SLOPIFY_DOWNLOAD_DIR` и адрес gRPC-загрузчика в `SLOPIFY_DOWNLOADER_ENDPOINT`. Для сборки Rust API нужен компилятор `protoc`.
